- P1 CONFIRMED + FIXED — `dog_detect.detect()` crashed on exactly 1 kept component (`ValueError: not enough values to unpack (expected 3, got 1)`). It fires only when an intermediate frame contributes zero nodes (repro: nodes t0+t2 → +1 edge `[[1,3]]`). Under the fixed/official scorer (S2 consecutive-frame filter) a t→t+2 edge is score-NEUTRAL: repro `pred [[1,3]]` vs chain GT scores `ec={TP:0,FP:0,FN:2}` — neither TP nor FP. So the pass cannot move the honest number; EXP-0017 "adds ZERO edges" reads as a scorer-neutral no-op, not evidence of a useful link step. No logic change (would be direction invention); added scorer-note docstring + id guard/self-edge guard (below).
- P3 CONFIRMED + FIXED (provenance; tie behavior documented, solvers unchanged) — (a) Tie divergence is real: brute-force search found trial 26 where pure-python and scipy optima pick different edge sets (`pure {(0,103),(2,101)}` vs `scipy {(0,103),(2,102)}`) at IDENTICAL total cost (2000000004.0625) — both optimal, but the edge set (hence honest score) depends on installed backend. Solver choice is unchanged (no tuning); the fix is honest provenance (b). Repro: big pair (N=65→scipy) then small pair (N=3→pure) ended with `assign=pure`. Fix: `link()` now collects `backends` per `_pair` call and reports `assign` = single backend or `"mixed:…"` (repro multi-size video → `assign=mixed:pure+scipy`, `backends=['scipy','scipy','pure']`), plus new `assign_backends` list. `trusted_cv` only stores the string (no equality checks), so this is backward-compatible.
