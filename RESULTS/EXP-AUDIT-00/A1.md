Official semantics confirmed by code-read (not just behavior):
`metrics._evaluate_matched_graph` runs, in order: exact-duplicate dedup on
`(EDGE_SOURCE, EDGE_TARGET)` keep-first → consecutive-frame filter
`t_target - t_source == 1` (left-join NULLs fail the filter) → merge-collapse onto the same
`(matched_source, matched_target)` keep lowest `EDGE_ID` → out-degree cap keep 2 lowest
`EDGE_ID`s per source. Matching is per-timepoint `1/(1+d)` weights (`d <= max_dist`,
inclusive) in `float32` CSR via `scipy.sparse.csgraph.min_weight_full_bipartite_matching
(maximize=True)`, with the `-1` fill-empty retry + dense `linear_sum_assignment` fallback;
implicit-zero cover-completing ("phantom") pairs are kept as matches on every path.

Known residual risks (documented, out of A1 scope):
- Official dedup sorts matched-rows-first then `unique(keep="first")`; repo keeps the lowest
  edge id. If exact-duplicate edges ever disagree on the matched mask, official keeps the
  matched copy while repo keeps the lowest id. Fuzz (3000 scenes incl. duplicate injection)
  produced 0 diffs, so this corner was not observed; flagged for A2/A3 awareness.
- Without scipy, the pure-python fallback leaves sub-threshold phantom pairs unmatched
  while the official records them. Repo runtime envs install scipy (`requirements.txt`
  `scipy>=1.12`), so the bit-exact path is the live one.
- `linear_sum_assignment` hard-failure path: official would crash; repo stays robust via the
  Hungarian fallback. Deliberate deviation, never observed in fixtures/fuzz.
